# ADR-0001: Desktop UI with Tauri 2, Svelte 5 and TypeScript

- Status: Accepted
- Date: 2026-10-21
- Deciders: pbiview maintainers
- Related: [ADR-0004](0004-desktop-ready-architecture.md), [ADR-0005](0005-rust-svg-renderer.md)

## Context

`pbiview` must run on macOS (arm64), Windows (x64) and Linux. The UI needs:

- Phase 1: a model tree, a report outline, a properties pane, and a virtualized, sortable data grid with column statistics.
- Phase 2: absolute-positioned report pages with charts, slicers and cross-filtering.
- Open by file dialog, drag-and-drop, or CLI argument.
- A long-term path toward a Power BI Desktop-style editor (panes, docking, property editors, undo).

The spec recommends Tauri so Phase 2 can use SVG/Canvas. All parsing, evaluation and rendering stay in Rust ([ADR-0004](0004-desktop-ready-architecture.md), [ADR-0005](0005-rust-svg-renderer.md)), so the UI layer is a thin shell over Rust APIs.

## Decision

- **Tauri 2 (stable)** hosts the app. The Rust side is the `pbiview-app` crate in `app/src-tauri`.
- **Svelte 5 (runes) + TypeScript + Vite** for the front end in `app/`.
- **Typed IPC with `tauri-specta`**: Rust command signatures and payload types generate TypeScript bindings. The front end never hand-writes IPC types.
- `pbiview-app` is a workspace member but **not** a `default-member`, so `cargo build` / `cargo test` at the root do not need webview system libraries. The app is built by its own CI job.
- The webview **only displays** what Rust produces (model data, grid pages, report SVG) and handles interaction and hit-testing. Report rendering does not happen in TypeScript.
- Security posture for the webview:
  - No remote content. Strict CSP. Everything is loaded from the bundled assets.
  - Tauri capabilities allowlist only the commands and plugins we use (for example `tauri-plugin-dialog`).
  - File contents never reach the webview as HTML. Text from files is rendered as text, and SVG is generated by our renderer, not passed through from the file.
- Large data crosses IPC in pages (backend paging over Arrow), not as whole tables.

## Alternatives considered

| Option | Why not chosen |
|---|---|
| egui / eframe (pure Rust, immediate mode) | Single language and small binaries, but weaker for dense desktop UX: rich text, accessible trees and grids, docking panes, IME, and theming all need custom work. It is a viable fallback because the renderer is already in Rust. |
| Slint, Iced, Dioxus native | Smaller ecosystems for data grids and complex editors. Same custom-widget cost as egui. |
| Electron | Bundles Chromium and Node, so larger binaries and a larger attack surface. No benefit over Tauri for a Rust back end. |
| Tauri with React | Viable. Svelte has a smaller runtime, compiled reactivity and less boilerplate for a small team. Either works with `tauri-specta`. |
| Render charts in TypeScript (D3, ECharts, Vega) | Rejected in [ADR-0005](0005-rust-svg-renderer.md): no headless PNG without a browser, and logic would be duplicated between CLI and app. |

## Consequences

- Each OS uses its system webview: WKWebView (macOS), WebView2 (Windows), WebKitGTK (Linux). UI chrome may differ slightly between platforms. Report output does not, because the SVG and PNG come from Rust.
- Linux CI and builds need WebKitGTK development packages. The core crates stay free of them.
- App builds need Node/npm in addition to Rust.
- IPC is typed end to end. Changing a Rust command type regenerates the TypeScript bindings, and type errors surface at build time.
- A future editor can grow inside the same shell, because all mutations go through Rust commands ([ADR-0004](0004-desktop-ready-architecture.md)).
