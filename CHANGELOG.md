# Changelog

All notable changes to DashCraft (named pbiview before [ADR-0009](docs/adr/0009-naming-dashcraft.md); older entries keep that name). The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Documentation
- M6.1 decisions: revisioned document state and transactions (ADR-0012), save conflicts and recovery (ADR-0013), serialization and generated identifiers (ADR-0014), and accessibility verification (ADR-0015). Corrected the Desktop plan's provisional ADR numbering to preserve the accepted naming and ground-truth records.

### Changed
- `pbi-model::History` stages edits before publishing them, advances a monotonic revision only when document content changes, and reports the changed flag, revision and events. Undoing back to the saved content clears the dirty state.
- `dax.query`, `dax.evaluateMeasure` and `measures.values` report `documentRevision` captured with the matching model and engine snapshot; DAX result formatting uses that captured model.
- Renaming a column now also renames the default label of aggregated report fields (`Sum of Amount` → `Sum of Revenue`), so LINT003 no longer reports it after a rename.
- The source-preserving TMDL writer keeps the source's `ref table` (or other `ref`) lines even when only one object of that kind is left; before, such a line was dropped.
- The source-preserving TMDL writer keeps, in an edited file, the text of every object whose meaning is unchanged (comments, quoting, spelled-out default values such as `toCardinality: one`); before, the whole file was rewritten canonically. Deleting and recreating a relationship and undoing both now saves the original bytes.
- Saved TMDL takes Power BI Desktop's form (GT-4, M6 acceptance 14): Desktop's property order for columns, measures and relationships, new measures and columns after the table's last ones, and each edited file keeps its line ends (CRLF in Desktop-saved projects) and blank last line; a new file takes the project's prevailing style. After the same edits, DashCraft's save equals Power BI Desktop 2.159's byte for byte apart from new identifiers and two listed deviations ([reference/groundtruth/gt4/deviations.json](reference/groundtruth/gt4/deviations.json)). The Acme Outfitters example is regenerated in that order.
- `model.relationships` lists each relationship's `relationshipId`.
- The results of `model.relationship.create` and `model.relationship.delete` also give the relationship's cardinalities, cross-filter and security filter directions and active flag.
- `dashcraft detect`, `inspect` and `lint` are thin wrappers over the registry commands `doc.detect`, `doc.open` + `doc.inspect` and `doc.lint` (ADR-0007 migration plan, M6.10); their output and exit codes are unchanged. Their path must now be valid Unicode. `doc.lint` findings gain `object`, the offending object's id (as in `model.dependencies`), and `doc.open`/`doc.detect` name a missing input once: `cannot open <path>: no such file or directory` (naming the missing project file when it is one).
- M names are bound when a query is compiled, as in Power BI Desktop: a name that is not a step, parameter, query or library function fails the whole query with Desktop's message (`The name 'X' wasn't recognized.  Make sure it's spelled correctly.`), even in a step that is never used or inside `try`; a step's own name is not in scope in its initializer (`let Source = Source in …` refers to another query named `Source`), so recursion needs `@`. A misspelled library function (`Table.RowCnt`) is such an unknown name, while custom-connector functions and library functions DashCraft does not evaluate stay "unsupported". A call with the wrong number of arguments raises Desktop's message, which does not name the function. Renaming a query to the name of the step that references it is now allowed, since the reference still means the query.
- Opening and saving a PBIP project fingerprints its files faster: the size and file-count caps are checked before any file is read, and the files are read on up to 8 threads (Acme Outfitters: 8.8 → 5.8 ms per scan).

### Added
- Drillthrough (M9.4): `canvas.drillthroughTargets` lists the drillthrough pages of a data point and `canvas.drillthrough` filters one on the point's (or the selection's) values, keeping the source's filters when "Keep all filters" is on; drillthrough buttons work in the app.
- Synced slicers (M9.6): selecting or clearing in a slicer, or Clear all slicers, copies its selection to every slicer of its sync group (`syncGroup`) over the same fields on any page, hidden ones included, so they filter their pages as in Power BI.
- Bar and column charts highlight instead of filtering (M9.1): a point selected in another visual dims their bars and draws the selected part solid, as Power BI does by default and for "Highlight" interactions, unless the report's "selections filter other visuals" setting is on; the DataView's `highlights` carry the values. Pies, donuts, treemaps, funnels and combo charts still filter, with a warning.
- Bookmarks now set filter cards (M9.5): the report, page and visual filters a bookmark captures (by name, or by field) replace the saved conditions on the canvas, following "selected visuals only" and the Data switch; changed Top N filters are listed as not applied.
- Bookmarks now set visuals' sort order (M9.5): a captured visual's `orderBy` replaces its saved sort until another bookmark resets it, following "selected visuals only" and the Display switch.
- Bookmarks now show and hide visuals and groups (M9.5): a visual captured as hidden (`display.mode`) or a hidden group (`visualContainerGroups`) disappears from the canvas and is no longer queried, and the visuals it shows reappear, following "selected visuals only" and the Display switch. Spotlight and focus modes are listed as not applied.
- Page and bookmark navigators (M9.5) draw one button per page or bookmark instead of one labelled button: hidden and tooltip pages and the bookmark group follow the visual's formatting, buttons are laid out horizontally, vertically or in a grid, and the current page or the bookmark applied last is selected. Clicking a button goes to its page or applies its bookmark, in the app and through `canvas.click` (new hit ids `<visual>|navItem|<index>`).
- Bookmarks pane in the app (View → Bookmarks, M9.5): the report's bookmarks and groups in pane order; a click applies one and marks it current. **View** starts a slideshow, with a bar above the page tabs (Previous, the bookmark's name and position, Next, Exit or Esc) usable by keyboard.
- Bookmarks (M9.5, first part): bookmarks and bookmark groups are read from PBIR (`bookmarks/`) and PBIR-Legacy/PBIX reports. The new `report.bookmarks` lists them and `canvas.applyBookmark` applies one. Bookmark buttons on the canvas now work in the app and through `canvas.click`: they go to the bookmark's page and set its slicer selections and cross-filter, honouring "selected visuals only" and the data and display switches. Filters, hidden visuals, sort, drill state and formatting are not applied yet and are listed as such. The Acme Stores report's two bookmarks and their card values are in `expected.json`.
- External changes in the app (M8.2, M8.3): while a PBIP project is open, DashCraft checks its files every 1.5 seconds; when another program (Git, an editor, Power BI Desktop) adds, changes or deletes one, a notification bar names it and offers Reload (rereads the project; asks first when unsaved edits would be discarded), Keep mine (hides the bar for these changes; Save still asks before overwriting them) and Compare (the document, unsaved edits included, compared object by object with the files on disk: what differs, only here or only on disk, each property's value on both sides, where it is defined, and its TMDL or JSON text with the differing lines marked).
- Compare in the app (M8.3): File → Compare compares the document, unsaved edits included, object by object with its files on disk, another Power BI file or a PBIP or TMDL folder (for example another copy or branch of the project), in the same view as the external changes bar's Compare; nothing is changed.
- Report objects in `doc.diff` and Compare as their PBIR files (M8.3): a changed, added or removed page, visual or report shows its `page.json`, `visual.json` or `report.json` as a save would write it, unsaved edits included, instead of the JSON of its properties (legacy layouts keep the properties).
- External changes pushed to `serve` and MCP clients (M8.2): every 1.5 seconds the open PBIP projects are scanned, and when a document's set of files changed by another program changes, `dashcraft serve` sends a `doc/externalChanged` notification and `dashcraft mcp` a `notice` log message (`data.event: "doc/externalChanged"`) with the changed paths, empty again after a save or reload; the scan waits its turn among the document's edits, so the server's own saves are never reported.
- Auto recovery in the app (M8.1): on by default, every edit of an unsaved document is kept in the per-user data folder; when DashCraft stops before a save, the next start offers Document recovery (Restore reopens the file with the edits, unsaved and undoable; Open saved opens the file as it was last saved and keeps the edits for the next start; Discard deletes them). File → Options → Auto recovery turns it off and shows the folder.
- Recovery journals, headless part (M8.1): when the host turns recovery on, every edit, undo and redo of an unsaved document is journaled in the per-user data folder (never beside the project), and a save, reload or close deletes the journal. After a crash, `doc.recovery.list` shows the journals left behind, `doc.recovery.restore` reopens the document and replays them (unsaved; a step that no longer applies stops the replay and keeps the journal), and `doc.recovery.discard` deletes one. Nothing is restored without a request.
- Semantic diff, headless part (M8.3): the registry command `doc.diff` compares a document's current revision with its files on disk (the default), with another open document (`againstDocId`) or with another file or folder (`againstPath`). It reports the objects added, removed and changed (tables, columns, measures, relationships, roles, expressions, calculation items, pages, visuals and more) by path, with the changed properties' values before and after, where each side is defined and each side's text (`snippet`: TMDL for model objects as DashCraft writes it, JSON for report objects; at most 200 lines). Formatting-only changes and object ids are ignored.
- External changes, headless part (M8.2): the registry commands `doc.status` (revision, unsaved edits, undo/redo, whether `doc.save` can save in place, and the project files changed on disk by other programs), `doc.externalChanges` (the files added, changed or removed since the open or last save, which `doc.save` refuses as a conflict without `overwrite`) and `doc.reload` (rereads the document from disk under the same `docId`, dropping its undo history, loaded data and canvas state; unsaved edits need `"discardChanges": true`; a failed reload changes nothing; not available to agents). A reload advances the revision and sends `doc/changed` with `"reloaded": true`.
- Screen-reader runs in CI (A6, [ADR-0030](docs/adr/0030-screen-readers-in-ci.md)): the workflow `screen-reader.yml` builds the desktop app and walks the M6 editing and M7 formula bar journeys with NVDA on Windows, VoiceOver on macOS and Orca on Linux through Guidepup (`scripts/app-checks/screen-reader.mjs`), checking what each reader says at 32 steps. NVDA must pass every required step; VoiceOver and Orca are informational. Each run uploads what was spoken, a report per step and screenshots ([docs/ci.md](docs/ci.md#screen-readeryml-screen-readers-weekly-or-on-app-prs)).
- `dashcraft lsp` (M7.6): a Language Server Protocol server on stdin/stdout, so editors such as Neovim, Helix or VS Code (through a generic LSP client extension) get DashCraft's help in `.dax`, `.m` and `.tmdl` files: diagnostics with quick fixes for "did you mean" suggestions, completion, hover, signature help, go to definition, references, highlights and semantic tokens for DAX, and formatting for all three. TMDL files are checked with the rest of their `definition` folder; `--model <path>` (or the `model` initialization option) checks and completes DAX and M names against a model and reopens it when a file under it is saved. Setup in [docs/CLI.md](docs/CLI.md#lsp).
- Desktop app: the formula bar has Power BI Desktop's formula editor keys (M7.5b): Tab and Shift+Tab or Ctrl+] and Ctrl+[ indent and outdent, Ctrl+M makes Tab move to the next control (and back), Shift+Enter keeps the line's indentation, Ctrl+Shift+Enter inserts a line above, Alt+↑ ↓ move lines, Shift+Alt+↑ ↓ copy them, Ctrl+Shift+K deletes them, Ctrl+L selects a line, Ctrl+X and Ctrl+C without a selection cut and copy the line, Ctrl+Shift+\\ jumps to the matching bracket, Shift+Alt+→ ← widen and narrow the selection, and Ctrl+↑ ↓ and Alt+PgUp PgDn scroll. Each is one step of the editor's undo. The formula bar with its suggestion list, parameter info, descriptions and squiggles passes the automated accessibility checks ([docs/accessibility/m7-formula-bar.md](docs/accessibility/m7-formula-bar.md)).
- Desktop app: IntelliSense in the formula bar (M7.5a) for measures, calculated columns and calculated tables. The DAX is coloured and problems are underlined with a wavy line (the one at the caret is read by screen readers); typing a name, `[` or `'`, or Ctrl+Space, opens a suggestion list (↑ ↓ PgUp PgDn, Enter or Tab inserts, Esc closes) with each item's description beside it; `(` and `,`, or Ctrl+Shift+Space, show the function's parameters with the current one in bold; pointing at a name, or Ctrl+K Ctrl+I, describes it; Shift+Alt+F formats the expression. It uses `dax.tokens`, `dax.diagnostics`, `dax.complete`, `dax.signatureHelp`, `dax.hover` and `dax.format` on the open document. The app's bundle splits its dependencies into a separate chunk.
- TMDL formatter (M7.4c): the registry command `tmdl.format` (and `pbi_tmdl::service::format`) lays a `.tmdl` file out as Power BI Desktop writes it: indentation by depth (tabs, or 1 to 16 spaces), `keyword: value` and `name = value` spacing, blank lines before named objects and none before properties, expression blocks moved with their own indentation kept, comments and descriptions aligned, one line ending throughout. Only white space changes, and the result is read back and compared before it is returned. Files saved by Desktop and the TOM library come back unchanged, and copies with their layout damaged come back byte for byte.
- TMDL completion and hover (M7.4b): the registry commands `tmdl.complete` and `tmdl.hover` (and `pbi_tmdl::service::{complete, hover}`) work on half-typed TMDL. Completion offers the keywords Microsoft's TMDL reader accepts on the line (those of its object, at the database's compatibility level, without properties already set or after a child object), with `: `, ` ` or ` = ` to insert; the values of a property's type (`true`/`false`, enumeration names); and the tables, columns, measures, hierarchies, query groups and other objects a reference may name, across the files of the model folder. Hover describes a keyword's forms, value and level, an enumeration value, or a referenced object with its `///` description and where it is declared. Every keyword, value and reference in the models saved by Power BI Desktop and the TOM library is offered and hovered, and every offered keyword is accepted where it is offered.
- TMDL diagnostics (M7.4a): the registry command `tmdl.diagnostics` (and `pbi_tmdl::service::diagnostics`) checks a set of TMDL files the way Microsoft's TMDL reader loads them: unknown or misplaced keywords (with the closest keyword), wrong forms and values, keywords above the compatibility level, duplicate properties, conflicting declarations, references to missing objects across a model folder (including translations), properties after child objects, bad `ref` lines and syntax, with positions and a suggestion. The rules come from a catalog recorded from the TMDL reader (ADR-0029): 4,106 of its 4,109 keyword, form, level and value verdicts and all verdicts on 54 edited models match. New fuzz target `tmdl_service`.
- M formatter (M7.3d): the registry command `m.format` (and `pbi_m::service::format`) lays out an M query or section within a line width (default 100) with 4-space, other-width or tab indentation: one `let` step per line, operators leading continuation lines, `else if` chains, `try … otherwise`/`catch`, and records, lists, calls, types and function bodies broken only when they do not fit. Only whitespace changes: every token and comment is kept, and the output must parse to the same tree; a syntax error is returned as a diagnostic. Formatting the 268 M expressions recorded from Power BI Desktop, at the default width and at width 20 with tabs, gives the same results as before formatting.
- M hover, signature help and completion (M7.3c): the registry commands `m.hover`, `m.signatureHelp` and `m.complete` (and `pbi_m::service::{hover, signature_help, complete}`) work on half-typed M, scoping names as Power BI Desktop binds them (steps, function parameters, `each`, record fields, sections, `@`). Hover shows a step's definition, a parameter's type, a query, parameter, function or table of the document with its description and definition, or a library function's signature, flagging names DashCraft cannot evaluate; signature help follows the active argument of library functions, `#` constructors, the document's function queries and functions of the text; completion offers the steps in scope, then the document's names, keywords and Desktop's library, ranked by match, with quoted `#"…"` names and primitive types after `as`. Positions in UTF-8, UTF-16 or line and column. All 418 free names and 285 library calls of the queries of the Acme Outfitters example and the Microsoft samples resolve.
- M diagnostics (M7.3b): the registry command `m.diagnostics` (and `pbi_m::service::diagnostics`) checks an M query or section without evaluating it: syntax errors, unknown names with a "did you mean" from the document's queries, parameters and the library, wrong argument counts of library functions, and warnings for names DashCraft cannot evaluate (data access, custom connectors), with Power BI Desktop's messages. The M library gains `Expression.Evaluate`. Checked against Desktop: 29 new recorded M expressions on name binding and argument counts (268, all matching apart from one by-design decimal case) and the argument-count errors of all 941 library functions (suite `m-arity`); no false errors on the 44 queries of the Acme Outfitters example and the Microsoft samples.
- M library (M7.3, part 2): 49 table functions, checked against Power BI Desktop: `Table.Join` (every `JoinKind`, several key columns), `NestedJoin`, `AddJoinColumn`, `Group` (local grouping, comparers, typed aggregations), `Pivot`, `Unpivot`, `UnpivotOtherColumns`, `ExpandTableColumn`, `ExpandRecordColumn`, `ExpandListColumn`, `AggregateTableColumn`, `SplitColumn` (with `ExtraValues`), `CombineColumns`, `CombineColumnsToRecord`, `Transpose`, `Max`, `Min`, `MaxN`, `MinN`, `AddRankColumn`, `Schema`, `ColumnsOfType`, `FromValue`, `ToList`, `Partition`, `Split`, `SplitAt`, `Repeat`, `AlternateRows`, `ReverseRows`, `InsertRows`, `RemoveRows`, `ReplaceRows`, `Contains`/`ContainsAll`/`ContainsAny`, `PositionOf`/`PositionOfAny`, `RemoveMatchingRows`, `ReplaceMatchingRows`, `FindText`, `IsDistinct`, `MatchesAllRows`/`MatchesAnyRows`, `SingleRow`, `FirstValue`, `PrefixColumns`, `RemoveLastN` and `ApproximateRowCount`. DashCraft now has 514 library names (384 of Desktop's 941 functions), and all 239 recorded M expressions give Desktop's result apart from one by-design decimal case. On the way, conversion errors use Desktop's wording for lists, records, tables, functions, binaries and types, a record missing a column makes its row an error in `Table.FromRecords` (as in Desktop) instead of failing the table, and `Table.TransformColumnTypes` rejects structured types.
- M library (M7.3): 69 more M functions, checked against Power BI Desktop: `Splitter.SplitTextByAnyDelimiter`, `ByCharacterTransition`, `ByLengths`, `ByPositions`, `ByRanges`, `ByRepeatedLengths`, `ByWhitespace`, `Text.NewGuid`, `Text.PositionOfAny`, `Number.Bitwise*`, `List.Median`/`Mode`/`Modes`/`StandardDeviation`/`Covariance`/`Product`/`Percentile` and list editing (`InsertRange`, `ReplaceRange`, `MaxN`, `MinN`, `TransformMany`, …), `Date.WeekOfYear`/`WeekOfMonth`/`QuarterOfYear`, start and end of day, week and quarter, `Date.MonthName`/`DayOfWeekName` in 18 languages, `Date.AddWeeks`/`AddQuarters`, `Time.StartOfHour`/`EndOfHour`, `Date`/`Time`/`DateTime`/`DateTimeZone.ToRecord`, `Record.TransformFields`/`ReorderFields`, `Binary.*` (text encodings, lists, ranges, splitting) and `Json.FromValue`, plus the `JoinKind`, `JoinAlgorithm`, `JoinSide`, `PercentileMode`, `Occurrence` and `BinaryOccurrence` constants and 18 enum types. DashCraft now has 461 library names (335 of Desktop's 941 functions); 191 of 202 recorded M expressions give Desktop's result. Dates outside 0001–9999 now raise Desktop's error.
- M ground truth (M7.3): Power BI Desktop's whole M standard library (1,142 names: 941 functions with their parameters and types, 69 types, 132 constants and values) is recorded from its mashup engine and shipped as a catalog (`pbi_m::service::catalog`) for the coming M editor features; every M name DashCraft implements matches it. 177 M expressions (literals, operators, errors and every family of the library) are recorded from Desktop and compared value by value with DashCraft (`cargo test -p pbi-m --test groundtruth`): 149 give the same result, 27 use functions DashCraft does not have yet, and 1 differs by design.
- `dax.format` (M7.2): lays out a DAX expression or query: calls that fit stay on one line, longer ones put one argument per line, operator chains break before their operators, `VAR` blocks put `RETURN` on its own line, queries put `DEFINE`, `EVALUATE`, `ORDER BY` and `START AT` on their own lines. Options for the line width (default 80), indentation (spaces or tabs) and the case of keywords and of built-in function names; comments and single blank lines are kept; names and literals keep their spelling. Formatting is idempotent and never changes meaning: the result is re-parsed and must give the same syntax tree, or the text is left as it is. Text with a syntax error comes back unchanged with the error. Checked on Power BI Desktop: the 2,902 ground-truth queries, reformatted at width 40 with tabs and lower-case keywords and functions, return the same results as the originals.
- `dax.tokens` and `dax.references` (M7.1): every DAX token worth highlighting with its kind (keyword, function, user-defined function, table, column, measure, variable, parameter, query parameter, string, number, date, operator, comment), declarations marked and unknown names flagged; and the symbol at a cursor with its definition (a `VAR`, a function parameter, a query `DEFINE`) and every occurrence in the text, with the model object's id. Checked on the 2,507 queries Power BI Desktop ran without error in the ground-truth corpora: no error diagnostics and no unknown names. On the way, `dax.diagnostics` no longer reports a bare `[name]` as an unknown measure when the text calls an `INFO` function or a user-defined function (it may be a column of that function's table), and `NAMEOF`'s component (`PARENT`, `SELF`, …) is a keyword.
- `dax.complete` (M7.1): DAX completion at a cursor while the text is being typed: functions (with their signature), tables, columns and measures of the open document, the variables in scope, a query's own `DEFINE`s and the keywords that fit there; inside `[` only columns and measures, inside `'` only tables and qualified columns, nothing in comments, strings or after `VAR`. Matches are ranked exact, prefix, word start (`Sal` finds `[Total Sales]`), then contains, and what the parameter being typed takes comes first (tables in `SUMX(`, columns in `SUM(`). The result gives the range to replace and the text to insert, capped at `maxItems` (default 100) with an `incomplete` flag.
- `dax.signatureHelp` and `dax.hover` (M7.1): the DAX function call around a cursor (signature, parameters, return type, the parameter being typed) and a description of the function, table, column, measure, variable or keyword under it (data type, expression, format string, the query's own `DEFINE`s); both answer while the text does not parse yet. They draw on a new catalog of every DAX function DashCraft evaluates, with DashCraft-written one-line descriptions. Cursors are given as a UTF-8 or UTF-16 offset or a line and column.
- `dax.diagnostics` reports wrong argument counts (`argumentCount`: "`SUM` takes 1 argument but 2 were given: SUM(column)"). The counts are checked against Power BI Desktop: 929 probes recorded from Desktop 2.159 (`reference/groundtruth/recordings/dax-arity.json`), and DashCraft agrees on all 815 where Desktop's answer is about the argument count.
- `dax.diagnostics` (M7.1, the first DAX language-service command) checks a DAX expression or query without loading data: syntax errors, unknown tables, columns and measures with a "did you mean" suggestion, and functions DashCraft cannot evaluate yet (a warning). Positions are given as UTF-8 and UTF-16 offsets and as line and column. With a `docId` the names come from the model and the report-level measures; without one, only syntax and functions are checked. No false errors or warnings on any of the 136 DAX expressions of the Acme Outfitters example and the four committed Microsoft samples.
- DAX `NAMEOF`: the name of a measure, column or table as DAX text (`'Sales'[Qty]`), with the `TABLE`, `COLUMN`, `MEASURE`, `FULL`, `SELF` and `PARENT` components and Power BI Desktop's errors; 298 → 299 functions. 17 new cases match Desktop 2.159.
- M6 runtime foundation: session-owned revisioned document edits with undo/redo and dirty-state tracking, exposed through `model.setMeasureExpression`, atomic grouped `doc.applyEdits`, and `doc.undo`/`doc.redo`/`doc.history`. Dirty documents now require explicit discard to close; conversions reject unsaved edits until writer synchronization is implemented. `model.measures` now includes stable object IDs.
- M6 editing commands: `model.object.rename` renames a table, column or measure as one undoable edit. Relationships, hierarchies, sort-by columns and report fields follow, and DAX references are rewritten at token level, keeping formatting and comments. The rewrite covers measures, calculated columns and tables, calculation items, format string expressions, RLS filters and derived columns. The loaded data is kept without a refresh, and `dryRun` previews every rewrite. Also added: `model.object.setDescription`, plus `report.visual.move` and `report.visual.resize`. `doc.applyEdits` gains `renameObject` and `setVisualPosition` edits. The registry grows from 47 to 56 core commands.
- `report.visual.move` and `report.visual.resize` move and resize visual groups (M6.5): the visuals in a group go with it (offsets stored relative to the group are kept on a move and scaled on a resize unless the group scrolls), results list them as `members`, and a move then a resize of the same visual in one `doc.applyEdits` compose. Power BI Desktop saves the same positions for the same edit and shows DashCraft's saved group where it belongs (GT-6).
- M-aware rename (M6.7): `model.object.rename` with `expression` renames an M query, parameter or function. Every M reference to it in table partitions and other expressions is rewritten at token level, quoted as `#"…"` when the new name needs it, and listed as `mRewrites` (also in the `dryRun` preview). Partitions that read the expression and the `PBI_QueryOrder` annotation follow, and so does a table rename when the table is an M query. Query names are unique among expressions and M tables, ignoring case. A name M cannot follow is refused: one of the referring query's own steps, parameters or fields, or a library function. Power BI Desktop opens and refreshes the saved project to the same values (GT-6).
- Renames follow into report-level measures (M6.7): the measures of a PBIR report's `reportExtensions.json` move with a renamed table, their DAX and `references` are rewritten, `model.dependencies` and deletes list them, a rename onto one of their names is refused, and `doc.save` writes them back (only the changed strings). Report fields whose names contain parentheses (`Orders.Sales (Scaled)`) now follow a table rename. Power BI Desktop loads the renamed report and computes the same card values (GT-6).
- M6 measure commands: `model.measure.create`, `model.measure.update` and `model.measure.delete`, each one undoable edit.
  - Create checks that the name is unique across the model and does not clash with a column.
  - Update patches only the given properties (expression, format string, display folder, description, visibility); an empty text clears one.
  - Delete lists what referred to the measure first: DAX expressions, report, page and visual fields and filters. `dryRun` only lists them.
  - DAX that does not parse is kept, with a warning. Undo restores a deleted measure with its id, and ids are never reused.
  - `doc.applyEdits` gains `createMeasure`, `updateMeasure` and `deleteMeasure` edits.
- `model.dependencies` lists what refers to a table, column or measure: DAX, relationships, hierarchy levels, sort-by columns, role permissions, and report, page and visual fields and filters. The registry grows from 56 to 60 core commands.
- M6 save: `doc.save` writes the edits into the PBIP project the document was opened from ([ADR-0013](docs/adr/0013-save-conflicts-and-recovery.md)).
  - Only files whose content changed are written, each atomically (temporary file, then rename). Everything else keeps its bytes: unknown properties, formatting, untouched numbers.
  - A table rename moves its `.tmdl` file; renames are applied to the report JSON (fields, filters, bookmarks), and visual moves patch only the `position` numbers.
  - A project file changed on disk since the open or the last save makes the save fail with the new `conflict` error code (exit code 1), listing the files; `"overwrite": true` saves anyway.
  - The project folder must be inside a write root. PBIX, PBIT and `model.bim` sources have no in-place save. The registry grows from 60 to 61 core commands.
- M6 Save As: `doc.saveAs` writes the document, edits included, as a new PBIP project from any source (PBIP, PBIX, PBIT, `model.bim`, a semantic model folder) and moves the document there.
  - Later `doc.save` calls write into the new project; the document is clean and keeps its undo history and object ids.
  - A PBIX's imported data and a PBIP's `.pbi/cache.abf` are not carried over, and a warning says so; data already loaded stays in memory.
  - The folder must be inside a write root and empty unless `"overwrite": true`. Report changes to a legacy-layout report (`report.json`, a PBIX `Layout`) are refused.
  - `convert.pbip` and `convert.pbit` now include unsaved edits (they used to refuse an edited document) and leave the document where it is.
  - The registry grows from 61 to 62 core commands.

Before, the dependency planner ignored the self-reference. Bare `[Column]` references in a calculated table's expression (`ADDCOLUMNS(CALENDAR(…), "Year", YEAR([Date]))`) still name the columns it iterates.
- Save: renaming a table, column or measure that a visual uses and then deleting it no longer makes `doc.save` and `doc.saveAs` refuse with "visual … has changes DashCraft cannot write yet"; the report keeps the new name, as in Power BI Desktop. Found by the registry property tests.
- Field parameters: the group-by columns of a column (`relatedColumnDetails`, e.g. a field parameter's display column grouped by `Parameter Fields`) are read from PBIX/PBIT metadata, TMDL and TMSL and written to TMDL and TMSL in each format's shape; aggregating such a column alone (`DISTINCTCOUNT`, `MIN`, `SUM`, …) gives Desktop's "part of composite key" error (ground-truth ledger 2 → 1 entry).
- DAX context semantics now match Desktop (ground-truth ledger 6 → 2 entries): every iteration starts a new `ALLSELECTED` shadow context (the filters at its start plus the iterated table), so `ALLSELECTED` inside `SUMX`/`FILTER`/`ADDCOLUMNS` and the implied relation of `OFFSET`/`WINDOW` give Desktop's values, and the table form `ALLSELECTED(T[c])` keeps only the shadow's filters on `c`; `KEEPFILTERS` around an iterator's table makes context transition intersect with the existing filters and is an error elsewhere; `IGNORE` outside a `SUMMARIZECOLUMNS` expression is an error, and `SUMMARIZECOLUMNS` with only ignored expressions keeps every combination; `CROSSFILTER` refuses a one-way direction from the many side to the one side.
- DAX semantics found by the Desktop ground truth: `AND`/`OR` of two BLANKs is FALSE; `MIN`/`MAX` with a BLANK argument; `STDEV.S`/`VAR.S` and their X forms give NaN for one value; `MEDIAN` over dates is an error; `EDATE` rounds its months; `REPT` with 0; `DISTINCTCOUNT` and `COUNTBLANK` do not count the relationship blank row; `PERCENTILEX.*` count a BLANK result as 0; `NETWORKDAYS` reads a text weekend as a number; `OFFSET` without a current row; `FORMAT` (many standard and custom number and date rules, out-of-range dates are errors); case variants of a text value in a computed column take the first spelling ([FUNCTIONS.md](crates/pbi-dax/FUNCTIONS.md)).
- Engine: a table gets its blank row when any relationship, active or inactive, has unmatched rows (BLANK ship dates now show as "(Blank)" on the Acme Year slicer and ship-month chart, as in Desktop); relationships between a Text and a Number key column join `"155"` to `155`.
- PBIT export: Power BI Desktop opens the templates DashCraft writes (the `Settings` part no longer has a `QueriesSettings` without `Version`, and hierarchy levels get explicit ordinals); Desktop computes the same values from DashCraft's PBIP (643 of 643 recorded queries) and PBIT (642 of 643; Desktop resets one custom date format on template import).
- Acme Outfitters example: measures with a dynamic format string no longer also carry a static `formatString`, and the `Products Never Sold` table no longer names a variable `Catalog`; both made Desktop refuse to load the model.
- Dependencies: rusqlite 0.41.1 and libsqlite3-sys 0.39.1; synthetic SQLite fixture builders use the new mutable serialization API, fixing their compilation.
- Dependencies: resvg and usvg 0.49.0 pick up upstream clipping and text-layout fixes; bundled-font and offline image-loading policies are unchanged.
- Dependencies: roxmltree 0.21.2 avoids stack overflow on deeply nested XML; ZIP 9.2.2 and the Tauri dialog plugin 2.8.4 pick up upstream maintenance fixes.
- Dependencies: Arrow and Parquet 59.3.2 maintenance fixes for IPC validity buffers, array offsets and Parquet decoding; DataFusion remains on 55.2.
- CI: replace the yanked transitive `async-executor` 1.14.0 with 1.14.1; the session unsupported-DAX regression uses a deliberately unknown function now that `PMT` is supported.
- Skipped entries of a folder (symlinks, ignored and unreadable files) are listed in path order on every OS, like the other entries.
- TMDL ↔ TMSL conversion keeps dynamic format strings: the `formatStringDefinition` object form is converted in both directions.
- One-to-one relationships relate each side's unmatched rows to the other table's blank row.
- The people transform ("Parse people field", `text.parsePeople`) accepts plain lists of names as well as lists of person records.
- `kpi` visuals use the `TrendLine` field as the trend axis (indicator and goal at its last point).
- Matrix row and column levels follow each column's sort-by column.

## [0.2.0] — 2026-10-22 — Phase 2: Report Renderer

Renders report pages offline, headlessly (`pbiview render`) and interactively in a Power BI Desktop-style app, from the data and engines of Phase 1. Also adds the remaining formats of [FORMATS.md](FORMATS.md) §5, PBIP local-cache data, a larger DAX library and session-derived columns.

### Added

#### Report renderer (`pbi-render`)
- **Theme resolution**: built-in fallback, base and custom themes deep-merged; `ThemeDataColor{ColorId, Percent}`; `visualStyles` precedence (visual `objects` → theme per type and preset → `"*"` → built-in defaults); primary and derived text classes.
- **Layout**: page size and scaling (`FitToPage`, `FitToWidth`, `ActualSize`), page background and outspace, paint order (z, then tab order), visual groups, container chrome from `visualContainerObjects` (background, border with radius, drop shadow, padding, title with auto titles and wrapping).
- **Visual queries**: `queryState` projections, report/page/visual filters, slicer selections and selected data points (per `visualInteractions`) → `EVALUATE SUMMARIZECOLUMNS` → Power BI-shaped DataViews (`single`, `categorical`, `table`, `matrix`) with totals and subtotals, implicit measures, default sorts, query limits and formatted cells. Report filters skip visuals with no relationship path to the filtered table. Filters that can't be applied are reported, never dropped silently.
- **Visuals**: `textbox` (rich runs, lists, links, overflow scrollbar), `shape`/`basicShape` (22 shape kinds), `actionButton` (icons, text, actions), `cardVisual`, `card`, `multiRowCard`, `kpi`, `slicer` (dropdown, list, tiles, range) and `advancedSlicerVisual`, `tableEx` (auto-sized, wrapping, banded, scrollable), `pivotTable` (stepped or tabular, subtotals, expansion), pie and donut (leader-line labels), clustered/stacked/100% bar and column, line, area, stacked area, line + column combos (axes with nice ticks, legends, data labels, `dataPoint` colors, category scrolling). Other types draw a placeholder with their fields; failed queries draw ⚠ "Can't display this visual".
- **Service quirks reproduced**: the new card's inner tile border and label clipping below ~100 px, honoured card font sizes, slicer header truncation, table auto-sizing and wrapping, pie label placement and truncation, Calibri metrics, browser line metrics.
- **Output**: retained scene graph with hit ids → deterministic SVG and PNG (`resvg`, bundled Selawik fonts only: byte-identical on every OS).
- **Golden-image comparison** (`pbi_render::golden`): page alignment, per-region Gaussian SSIM, diff heatmaps (written under `target/` only).
- Interactive rendering API: `query_page_data` + `render_interactive_page` (scroll, expansion, open dropdowns as an overlay, per-visual interactive geometry), `InteractionState::from_page` (selections saved in the report).

#### CLI
- `pbiview render`: `--png`, `--svg`, `--out-dir` with `--format png|svg|both`, `--report`, `--page` (name, display name, index or part of it), `--all-pages`, `--scale` (default 2, at most 16), `--slicer "SLICER=V1,V2"` (`!=` to invert, `=` to clear), `--now` for reproducible clocks, `--json` per-visual status. Exit code 2 when the refresh or a visual fails.
- `refresh`, `measures`, `export --table` and `render` take `--source auto|m|cache`; `auto` (the default) loads a PBIP's `.pbi/cache.abf` when present and notes it on stderr. `refresh --json` reports `kind: "cache"`.
- `export --excel-safe` turns on the CSV formula-injection guard.

#### Desktop app
- **Power BI Desktop-style shell** (read-only): title bar with search (Alt+Q), ribbon with Desktop's tabs and groups (unsupported commands disabled with a tooltip), File backstage with persisted **Recent** files, view rail (Report, Table, Model, DAX query, TMDL), Filters / Visualizations / Data / Selection / Properties panes, formula bar, page tabs, status bar with zoom. Fluent UI System Icons (MIT) and Selawik (OFL); no Power BI assets.
- **Interactive report canvas**: the page rendered by `pbi-render` as sanitized SVG; slicers (single and multi-select, Select all, dropdown popups, search, clear), cross-filtering from pie, bar, column, line, table and matrix points per `visualInteractions`, data-point and error tooltips, table and matrix scrolling, matrix expand/collapse, Back and page-navigation buttons (Web URL shown, never opened), Reset to default, keyboard focus. Renders are cancellable and query results are cached per page.
- Filters pane cards follow view-mode rules (hidden cards, locks) and list the canvas's selections; the Measures panel evaluates in the canvas's filter context by default.
- **DAX query view** (`EVALUATE` with `DEFINE`/`ORDER BY`, run selection, cancel, results with copy, quick queries), **TMDL view** (verbatim or generated), **Model view** diagram (`diagramLayout.json` positions or auto-layout), read-only **Transform data** editor, Design → Themes, Format pane cards.
- **Local data cache**: a PBIP with `.pbi/cache.abf` loads its cached data on open, with a "Loaded cached data (as of …)" banner and **Refresh from source**.

#### Engines and session
- **DAX** (`pbi-dax`): 210 functions (187 supported, 23 partial; up from about 120), including time intelligence, `ALLSELECTED` (shadow filter context), `ISINSCOPE`, `ROLLUPADDISSUBTOTAL`/`ROLLUPGROUP` in `SUMMARIZECOLUMNS`, `RANKX`, window functions (`INDEX`, `OFFSET`, `WINDOW`, `RANK`, `ROWNUMBER`), statistics, parent-child functions, `USERELATIONSHIP` and `CROSSFILTER`. Coverage table: `crates/pbi-dax/FUNCTIONS.md`, kept in sync by tests.
- **Storage engine** (`pbi-engine`): per-filter-context relationship overrides (activate inactive relationships, change cross-filter direction).
- **Derived columns** (`pbi-session`): `Session::add_derived_column` / `remove_derived_column` / `derived_columns` with `DerivedColumn::People` ("Parse people field"), `Expression` (DAX) and `Array`. Stored in the engine table, so DAX, SQL, the grid, statistics and exports (Parquet field metadata `pbiview.derived = true`) see them; re-applied in creation order after every refresh, cache load and CSV load; never saved to the model. Name collisions with a column or measure are errors.
- **PBIP local data cache**: `Session::load_cached_data` maps `<Model>.SemanticModel/.pbi/cache.abf` onto the model by name (no M, no network). Calculated objects missing from the cache are computed; a missing table fails with a "refresh from source / Load CSV" hint; a missing data column loads as BLANK with `SESSION005`. `RefreshOptions::source` (`Query`, `Cache`, `Auto`), `Session::cache_info`, `has_cached_data`, `RefreshKind::Cache`.
- **CSV formula-injection guard**: `CsvExportOptions::escape_formulas` (off by default) prefixes text cells and header names that start with `=`, `+`, `-`, `@`, TAB or CR with `'`; numbers, dates and booleans are never changed.

#### Formats
- **Excel Power Pivot** (`.xlsx`/`.xlsm`): model **and data** from `xl/model/item.data`, with per-file Xpress (MS-XCA Plain LZ77) decompression and legacy XML metadata (compatibility level 1100/1103, `.tbl.xml` storage).
- **VPAX**: model (from `Model.bim` or rebuilt from `DaxModel.json`) and VertiPaq Analyzer statistics.
- **RDL** paginated reports: outline of data sources (connection strings always redacted), datasets, parameters and report items; DTDs refused, sizes capped.
- **Power Query**: `.pq`/`.m` scripts, `.pqt` templates, dataflow `model.json` (CDM entities as tables with M partitions), Dataflow Gen2 definitions.
- **Custom visuals and connectors**: `.pbiviz` metadata and `.mez`/`.pqx` listings; never executed.
- PBIP `.pbi/cache.abf` metadata part (`inspect` → `model.cacheAbf`). New `inspect --json` sections (additive, `schemaVersion` 1): `vpaxStats`, `paginatedReport`, `mashup`, `customVisual`, `connector`.

#### Packaging
- Original app icon (no Microsoft or Power BI marks), bundles for macOS (app + dmg, arm64 and x64), Windows (msi + nsis) and Linux (AppImage + deb), and file associations for `.pbix`, `.pbit`, `.pbip`, `.bim` and `.vpax` (viewer role, not claimed as default). The GUI binary is `pbiview-app`; the `pbiview` CLI ships as separate per-OS archives.
- macOS document opens (Finder double-click, "Open With") reach the running app as an `open-file-requested` event; Windows and Linux pass the path on the command line.
- Release workflow: tag/version consistency checks, release notes from this changelog, SHA-256 sums, CycloneDX + npm SBOMs, signing and notarization only when the secrets exist (unsigned builds otherwise). License inventory generated into `THIRD_PARTY_NOTICES.md` (`scripts/license-inventory.py`); see [docs/packaging.md](docs/packaging.md).

- Golden-image regression tests against Power BI service exports (per-region SSIM ≥ 0.85; regions whose text uses fonts pbiview does not bundle, such as DIN titles and Calibri text, have documented lower thresholds). Card values are asserted on the rendered scene and SVG for each report.
- Renderer unit and reference tests per visual family; CLI end-to-end `render` tests (determinism, JSON status, exit codes); app tests that drive the canvas through Tauri's mock runtime.
- Docs: rewritten README with format and visual matrices, [docs/CLI.md](docs/CLI.md), [docs/USER-GUIDE.md](docs/USER-GUIDE.md), [docs/VISUALS.md](docs/VISUALS.md), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), final [FORMATS.md](FORMATS.md), [ADR-0006](docs/adr/0006-interaction-state.md).

- The app's "Parse people field" uses the `pbi-session` derived-column API: the column is now visible to measures, DAX queries, SQL filters and exports, not only the grid.

### Known gaps
- **Renderer**: highlight interactions filter instead of highlighting; bookmarks, drillthrough, Q&A, synced slicers, report-page tooltips, visual header menus, drill-down/up, conditional formatting, the Analytics pane and small multiples are not supported; range-slicer sliders are not draggable; `image` visuals and wallpaper images are not drawn; other visual types (maps, funnel, treemap, gauge, scatter, waterfall, AI and custom visuals) are placeholders.

## [0.1.0] — 2026-10-21 — Phase 1: Data Explorer

Opens Power BI files offline on macOS, Windows and Linux, without Power BI Desktop, a Windows VM or a Fabric login.

### Formats
- **PBIP** projects (folder or `.pbip`):
  - Models in TMDL or legacy `model.bim`.
  - Reports in PBIR or PBIR-Legacy.
  - `byPath` and `byConnection` dataset references; a `byConnection` model is shown as remote.
  - Also reads `.platform`, `definition.pbism`, `.pbi/localSettings.json` and `diagramLayout.json`.
- **PBIX**:
  - Report from PBIR (`Report/definition/`) or the legacy `Report/Layout`.
  - Model schema and **embedded data** from `DataModel`, decoded by a clean-room XPress9 + ABF + VertiPaq implementation.
  - `SecurityBindings` is treated as opaque.
- **PBIT**: `DataModelSchema` (TMSL, UTF-16LE) plus the report.
- **Other inputs**: standalone `.bim`, TMDL folders, `.pbids`, and `.abf`.
- **Detection by content**: ZIP entries, JSON keys, `$schema` and encoding decide the format, not only the extension.
- **Lossless round-trips**:
  - TMDL re-emits byte-for-byte.
  - The PBIR writer reproduces all fixture files byte-for-byte.
  - TMSL preserves its layout.
  - Unknown fields are always preserved.

### Engines
- **M (Power Query) evaluator**:
  - Lazy, with closures, `each`, `try`/`otherwise`, `meta` and sections.
  - About 200 library functions, including `Csv.Document` and the `Table.*`, `Text.*` and `List.*` families.
  - `AzureStorage.Blobs` resolves through an offline blob map (`blob-map.json`). M code has no file or network access.
- **DAX formula engine**:
  - Filter and row context, context transition, expanded tables, blank semantics.
  - `CALCULATE` modifiers, about 120 functions including `FORMAT`.
  - `DEFINE`/`EVALUATE` queries, calculated columns and tables.
- **Storage engine**:
  - Arrow columnar store with relationship indexes (blank row included).
  - Single and bidirectional filter propagation; a table with no relationship path to the filter is unaffected.
  - DataFusion SQL for the grid.
- **Refresh**:
  - Order is M partitions, then calculated columns, then calculated tables, by dependency.
  - Transactional and cancellable, with a per-table status.
  - When a table fails, "Load CSV manually…" is offered as a fallback.

### Explorer
- **CLI** (`pbiview`): `inspect [--json]`, `detect`, `open`, `convert --to pbip|pbit`, `lint`, `refresh`, `measures [--report]`, `export`.
  - The `inspect` and `lint` JSON outputs carry `schemaVersion: 1`.
- **Desktop app** (Tauri 2 + Svelte):
  - Open by dialog, drag-and-drop or command-line argument.
  - Model tree, relationships, M/DAX code views, report outline with a wireframe preview and filters, Properties pane, diagnostics.
  - Virtualized data grid with sorting, filters and column statistics.
  - Refresh with progress; measures panel with values under report filters; "Parse people field".
- **Linter**: 17 broken-reference rules, each pointing at the file and JSON pointer, with did-you-mean suggestions.
  - It detects stale `queryRef`s left behind by renamed measures or columns.
- **Exports**: table to CSV or Parquet; model to a JSON or Markdown data dictionary, including `///` descriptions.

### Verified
- Measure and card values under report and page filters, row counts after the M steps, and the "no relationship path" filter behaviour are asserted in tests against independently computed expected values.
- Decoded PBIX data is cross-checked against pbixray (MIT) by hash.

### Security
- All input is treated as untrusted:
  - Zip-slip and decompression-bomb guards; symlinks are never followed.
  - Size, entry and recursion limits.
  - No `unsafe` code; parsers never panic.
- 14 cargo-fuzz targets, run nightly in CI. Fuzzing found and fixed a drive-letter zip-slip bypass.
- Embedded scripts, custom visuals and connectors are never executed. There is no telemetry.
- Connection strings and secrets are redacted from metadata.

### Known gaps
- **Report rendering** is Phase 2. The app shows a wireframe preview only.
- **M, DAX and storage engine coverage**:
  - Not supported: DAX time intelligence, `USERELATIONSHIP`/`CROSSFILTER`, calculation groups, and many-to-many relationships.
  - M ignores culture settings.
- **PBIP cache data**: `.pbi/cache.abf` data loading, `.vpax`, `.rdl`, `.pqt` and Excel Power Pivot are detected but not read yet.
- **Release status**:
  - The "Parse people field" derived column is session-only and visible to the grid only (not to DAX/SQL/exports yet); column statistics cover the whole table, not the filtered view.
- CSV exports do not yet offer an opt-in spreadsheet formula-injection guard.
- Release artifacts are unsigned until signing certificates are configured.
  - Shipping PBIX data decoding needs the legal review recorded in ADR-0003.
