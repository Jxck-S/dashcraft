# FORMATS: support matrix

Formats are detected **by content**, not by extension: ZIP entry names, JSON keys, `$schema` URLs, XML namespaces and text encodings decide. Extensions are only a hint, used for the file dialog and as a tie-breaker. Detection lives in `pbi-core::detect`; [`pbi_core::open_path` / `open_bytes`](crates/pbi-core/src/reader/mod.rs) dispatch to a reader and return an `OpenedDocument` (a unified `pbi_model::Document` plus the container, the parsed sources and a format outline). Formats that are detected but have no reader (for example other Fabric item folders) open with the entry listing and an Info diagnostic (`CORE002`).

Containers (folders or ZIP) are opened with caps on total uncompressed size, entry count and compression ratio, a zip-slip guard (absolute, `..` and drive-letter paths are refused) and no symlink following.

Metadata parts (`.pbip`, `definition.pbism`, `.platform`, `.pbi/localSettings.json`, `diagramLayout.json`, PBIX `Version`, `Settings`, `Metadata`, `DiagramLayout`, `Connections`, `.pbids`) are parsed leniently into `OpenedDocument::parts` after **redaction**: values under keys containing `connectionString`, `password`, `pwd`, `token`, `key`, `secret` or `credential` become `<redacted>`, and secret parameters (`sig=`, `accountkey=`, …) inside other strings are masked. A report's `byConnection.connectionString` keeps its server and model but has secret parameters masked.

## Levels

- **Explorer**: *Full* — model tree, code views, data grid, exports. *Model* — model tree without data. *Outline* — structural outline. *Metadata* — properties only. *Listing* — file list only.
- **Data** (how table data is loaded by `pbi-session`): *VertiPaq* — embedded data decoded by `pbi-vertipaq`. *M refresh* — partitions evaluated offline by `pbi-m` (`AzureStorage.Blobs` through a blob map; other data-access functions fail with a "Load CSV manually…" fallback). *Cache* — a PBIP's `.pbi/cache.abf`. *Stats* — statistics only. *none*.
- **Renderer**: *Full* — report pages rendered (supported visuals; others as placeholders, see [docs/VISUALS.md](docs/VISUALS.md)). *Placeholder* — a box with the type and fields. *n/a* — not a report format.

Fixture paths are relative to `reference/` (or `$PBIVIEW_REFERENCE`) unless they start with `crates/`. The main fixtures are the synthetic Acme Outfitters example (`examples/acme-outfitters/`) and the MIT-licensed Microsoft sample reports (`samples/microsoft/`; see [reference/samples/microsoft/README.md](reference/samples/microsoft/README.md)). "(optional)" marks gitignored files (larger samples fetched by `scripts/fetch-samples.sh` into `samples/downloads/`, golden images); tests that need them print `SKIP: <file> missing` and pass.

## Notes

- Text encodings: `Version`, `Report/Layout` and `DataModelSchema` are UTF-16LE. Readers detect the encoding from the BOM or NUL-byte pattern, and never assume it from the extension.
- PBIR `$schema` versions vary between files in the same report. Readers accept unknown versions and fields, and keep unknown fields round-trippable ([ADR-0004](docs/adr/0004-desktop-ready-architecture.md)).
- Writers: `pbi_core::save_as_pbip` (TMDL + PBIR, used by `convert --to pbip`) and `pbi_core::export_pbit` (`convert --to pbit`). PBIX is never written (it would need XPress9 and ABF encoders).
- Representation of the §5 formats: a paginated report is **not** mapped onto the Power BI report AST (its datasets, parameters and item tree have no PBIR equivalent, and a pseudo-page would mislead the renderer), so it is a dedicated `PaginatedReport` outline next to an empty document. M scripts, templates and Gen2 dataflows become models holding only named expressions (nothing is evaluated on open); CDM dataflows also have one table per entity with its M query as the partition. VPAX statistics, custom visual and connector metadata live only in the outline.
- Power Pivot backups (`xl/model/item.data`) set `ApplyCompression` and `ErrorCode`: every model file is stored as chunks of `u16` uncompressed size + `u16` compressed size + an [MS-XCA] Plain LZ77 block (stored verbatim when both sizes are equal), followed by a CRC marker. Their metadata is legacy XML (`*.cub.xml`, `*.dim.xml`, MDX script, `*.prt.xml`) and their storage is described by `*.tbl.xml` object trees instead of `.idfmeta` files. See [crates/pbi-vertipaq/FORMAT-NOTES.md](crates/pbi-vertipaq/FORMAT-NOTES.md) §4.4 and §5.3.
- Fixtures still wanted from a Windows machine with Power BI Desktop (see [docs/ROADMAP.md](docs/ROADMAP.md#next)): a PBIR-Legacy PBIP, a real `.pbi/cache.abf`, a Power Pivot workbook, a DAX Studio VPAX and a Report Builder RDL.
